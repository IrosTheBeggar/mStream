Flow and rules — read before building the view

The view is a thin client over an API that exists: the plug-in registry, the job gate, the sweep and the jobs list were built with the features, and the rest landed with this design (branch feat/discovery-plugins-admin, integration-tested). What is left to build is the view itself. This card says where it lives, what is live, and what is still undecided.

Where it lives

Nav: Config → Discovery Plugins, directly under Discovery (same cyan, plug icon). changeView('discovery-plugins-view'), a Vue.component registered beside discovery-view in webapp/admin/index.js.

One card, four tabs (Plug-ins · Jobs · Downloads · Activity), the Discovery view’s boxed header and pills. The tab is session-local. The header sentence and the Activity count are the only things shared between tabs.

Loading: on open, one GET …/discovery-plugins/status fills the header, Plug-ins, Jobs and Downloads; Activity loads when its tab is first shown. While a job is live, status and Activity refresh every 3 s; otherwise nothing polls. Leaving the view stops it.

Shared code: the admin page loads webapp/alpha/discover-jobs.js for jobRowState and fmtBytes, so state words and sizes match the user’s window exactly.

What is live

Everything on this view applies at once — switches, radios, ticks, settings, retention — and says so with a toast, because the server reads these values per request (registry), per tick (runner) or per pass (retention). No reboot blockquote, no APPLY button.

The one exception is not editable here: the downloads folder (discoveryJobs.downloads.dir). The scratch library’s row points at it, so it stays a config-file change with a restart, and the tab shows it read-only.

Nothing is destructive without a word. Switching a plug-in off hides its row from users; it does not cancel its running jobs or delete what it downloaded. Shortening retention names how many files become due. [cancel] on someone else’s job asks once (“Cancel dana’s download?”).

Decided18 Sep 2026 · still assumed

Nav: Config, directly under Discovery.

Layout: one card, four tabs (Plug-ins · Jobs · Downloads · Activity).

No “what leaves the server” line. Rows carry title, tags, description and status only; the registry keeps no such field.

Defaults stay as they are: the preview plug-ins ship switched on; YouTube ships off (it needs yt-dlp and lands files from outside).

A size cap on Discover downloads (Downloads card): 5 GB by default, 0 = none, checked before each download.

Still assumed, not yet confirmed: every control applies at once with a toast; there is no APPLY button on the access radios (Torrent’s “Enabled For” has one). One gate for every job plug-in, not one per plug-in.

Planned rows. Webhook and ListenBrainz are drawn on the row-states card only to prove the row holds “needs setup” and “2 of 8 users connected”. They are not part of this build.
