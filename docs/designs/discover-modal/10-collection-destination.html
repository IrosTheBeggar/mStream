Collection destination — set or choose the folder

Every Add … to your collection row and every Get it download lands in one destination: a library you can upload to, a base folder inside it (chosen by browsing, the library root by default) and a layout rendered from the song’s tags with the template engine torrents already use ({{ARTIST}}/{{ALBUM}}, same variables, same sanitising). A copy keeps the peer’s file name; a download keeps yt-dlp’s. The bar under the view selector always shows the path resolved for the song in the window; Change… opens the picker in place, and the choice is remembered for your account.

Hiddenthe only “not available” state

No Add rows, no Get it rows and no destination bar when this account may not create jobs, when uploads are off for this account (noUpload on /api/) or when it has no library it may write to; the Add rows also need the federation-copy plug-in on. The Federation view then holds Play, Queue, View album and View artist only. Nothing is shown locked, and the picker never lists a library you cannot write to.

Storage and ruleswhat the webapp saves and what the jobs do

Saved per account as user_settings · key destination = { vpath, base, layout }, read and written through GET/PUT /api/v1/discovery/collection/destination. Unset = the library default, computed on the server so the bar, the preview and the jobs agree.

The jobs render the layout per song with the torrent engine (resolveTemplate, plus the PEER variable), keep the file’s own name, create folders as uploads do, skip songs you already have (by hash, and by tags before a download starts) and never overwrite a file at the same path, then insert the row like a Youtube DL download so it plays at once, and write a record of where the file came from (plugin_downloads, the Downloads panel). Cancelling an album or artist copy keeps the songs that finished.
