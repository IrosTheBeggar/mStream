Get it — every state of a download

One row per acquire plug-in. Pressing Download creates a job (POST /api/v1/discovery/plugins/:name/jobs) and the row becomes that job: state, progress and status text come from discovery_plugin_jobs and refresh while the window is open. Only one live job exists per plug-in and recommendation, so re-opening the window finds the same row. Collection copies from a peer (Federation view) are the same job rows.

Hiddenthe only “not available” state

The row, or the whole section, does not render. No acquire plug-in enabled; a plug-in that is enabled but unconfigured (no slskd URL, no yt-dlp binary); jobs not enabled for this account (discoveryJobs.enabledFor = whitelist, the listing’s jobs.allowed); nowhere to put the file (uploads off for this account, or no library it may write to) — all of them look the same to the user: the option is not there. Nothing is ever shown locked or greyed out, and the API answers 404 for what the list omits.

The Federation view’s Add-to-collection rows follow exactly the same rules, and so does the destination bar above either (card 10).

With no plug-ins at all the Plug-Ins tab disappears on peer rows, and a network row falls back to today’s copy-to-clipboard.
